# Data Lineage 2.0：实现与边界

## 面向用户的交互

数据血缘入口提供 Cube / TI 两个独立视角，使用同一套对象搜索、自动补全、键盘选择与按模型隔离的会话历史。输入不会自动选择第一个匹配项。图负责显示关系，点击对象或关系查看摘要，证据与完整报告按需展开。保留旧路由和既有 Markdown / JSON 导出。

Cube 图只显示 Cube：同一 TI 中共同读写仅是候选；具体写入经现有解析器确认了源值依赖时才标记静态依赖，部分写入或结果截断时保留部分确认。Rule 引用与 TI 写入分别展示。每次查看写入独立呈现来源、目标切面和源码证据，不将一个写入点的坐标套到另一个写入点。无法确认的内容不视为运行时失败。

TI 图只显示直接或范围内的调用程序。源码调用、条件调用和仅由索引支持的入口有区别；动态目标与 Chore 单列。选择已分析范围内的节点时复用同一工作流结果，范围外节点须显式作为新入口分析。调用关系不表示运行顺序。

## 复用与范围

复用现有 Workbench 索引、写入点与 Rule 分析、Workflow 缓存、Mermaid 组件和导出；`lineage-view.js` 只是有界展示投影，不是解析器。图和 Mermaid 文本取同一投影。交互图最多显示 24 个节点、30 条边，超出的数量明确提示；报告保留本次后端查询范围，范围本身仍受深度、查询预算和 Rule 文件预算约束。完整结果不等于全模型或运行时验证。

`GET /api/workflow/tasks/{task}/review` 新增可选 `process`，仅允许本次工作流已分析的程序；不传参行为保持原有根程序。切换子程序不将原入口的间接调用错误归属于该子程序。

## 后续限制

源 VIEW 数值列与数据行变量缺少元数据时仍无法证明值流；动态坐标、未知表达式和预算之外的内容不得推断。图表控制器和页面接口已用合成数据测试，真实浏览器点击、缩放观感以及用户可用性测试仍须在可用的浏览器控制环境中完成。
