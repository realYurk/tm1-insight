# Next Product Decisions — 需要用户决策的方向

日期：2026-10-22 · 承接 `PRODUCT_QUALITY_REPORT.md`

## 1. 性能基准与大规模图（建议下一轮优先）

当前护栏：120 节点 / 300 边预算（超出优雅拒绝）。缺少：
- [ ] 100 节点合成模型 + 真实大快照的渲染/布局/拖动帧率测量报告；
- [ ] 超预算图的"局部展开"体验（当前是整体拒绝）。

需要决策：是否接受引入 ELK.js（~1MB）换取正交路由与更复杂的分层布局？

## 2. Portable 构建刷新

本轮新增 `canvas.css` / `canvas-layout.js` / `canvas-shell.js`。
- [ ] 重跑 `make_release.py` 并核对打包清单后发布新 Portable。
- [ ] 版本号与构建说明更新。

## 3. 撤销模型

无可靠命令历史，本轮未伪造 Ctrl+Z。若要支持：
- [ ] 设计草稿操作（建/删/改映射/生成）入命令栈，快照对象操作不入栈。

## 4. 模块（Module）的图语义

当前模块是视觉折叠（成员隐藏）。需要决策：
- [ ] 是否升级为"折叠为单一组节点 + 组级边聚合"？这会改变 `positions` 语义，
      需要工作区 schema v4 迁移。

## 5. Rule / Feeder 的画布表达深度

- [ ] Rule 线是否需要点击后直接展示表达式原文（当前在 Inspector 内）；
- [ ] Feeder 是否提供"仅技术层"开关图层（当前始终显示点线）。

## 6. 公开仓库历史风险（沿用，未处理）

`docs/security/PUBLIC_REPOSITORY_AUDIT.md` 列出的企业对象名与绝对路径仍在公开历史中。
需要用户决策：新建干净仓库迁移 / 接受现状 / 其他。本轮未做任何历史改写。

## 7. 通用分摊模块

Canvas-first 工作流完成后，按早前规划进入"可配置分摊"与画布的深度整合
（分摊链在画布上作为一等关系表达）。建议在 1（性能）之后启动。
