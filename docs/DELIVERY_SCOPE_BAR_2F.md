# 阶段 2 第六刀：范围变成一条常驻状态条

> 触发：用户再次「继续，该推推」。
> 上一刀把导出对齐了页面，但「当前视图被裁剪过」这件事仍然只说在侧栏一行小字里，
> 进了全量视图更是一点标记都没有。这一刀把它提到第一屏。

## 1. 用户问题

上一轮之后，范围在页面上共有三处痕迹：侧栏「已隐藏 N 条」小字、导出卡的一句话、
参数卡片下的警告。共同毛病是——**都在页面下半部分，且互不引用**。

具体三种失控情形：

1. 滑到列表就以为看到了全部，其实上面少了 3 条；
2. 点了「包含它们」进全量，页面上没有任何东西提示「你现在看的不是业务视图」；
3. 一个本来就没有系统对象的 TI，写着「已隐藏 0 条」，像在说废话，也让人怀疑是不是没生效。

## 2. 做法

新增共用宏 `api/templates/_scope_bar.html`，两页（计算检查、子 TI 参数检查）在
标题区下方各渲染一条，`role="status"`，屏幕阅读器也会念。

三态用颜色和文案分开，`data-mode` 决定样式：

| data-mode | 何时 | 颜色 | 文案示例 | 右侧链接 |
|---|---|---|---|---|
| `business` | 有 `}` 记录被排除 | 琥珀左边框 | 当前范围：18 条写入点 · 另有 3 条 } 前缀写入点未显示 | 看全部（含 } 前缀）→ |
| `all` | 显式 `system=1` | 蓝色左边框 | 当前范围：21 条写入点 | 只看业务对象 → |
| `none` | 该 TI 没有系统对象 | 灰色左边框 | 当前范围：5 条写入点 · 这个 TI 没有 } 前缀写入点 | 不给链接 |

`none` 态**刻意不渲染切换链接**：没有可切的东西时给一个能点的箭头，
等于承诺一个不存在的视图。宁可什么都不给。

## 3. 顺带清掉的重复

- 计算页侧栏原来的「已隐藏 N 条 · 包含它们」整行删除——状态条接管，避免两处数字不同步；
- 调用页导出卡里原来的「包含 } 前缀内容 / 只看业务对象」按钮删除——那是**切视图**，
  与状态条重复。导出卡只保留**下载**动作，另加一个「全量 JSON（含 } 前缀）」，
  因为「页面看业务、材料要全量」是真实需求，跟切换视图不是一回事。

## 4. 改了什么

| 文件 | 改动 |
|---|---|
| `api/templates/_scope_bar.html`（新增） | `scope_bar` 宏：版式 + 三态 + 切换链接，文案由调用方传入 |
| `api/static/workbench.css` | `.scope-bar` 及三态、暗色主题覆盖（约 30 行） |
| `api/templates/calculation.html` | 引入宏、标题区下方渲染、删除侧栏旧提示行 |
| `api/templates/invocation.html` | 引入宏、渲染；导出卡改为「全量 JSON」下载链接 |
| `tests/test_export_scope_parity.py` | 新增 3 条（三态各一） |
| `tests/test_calculation_api.py` | 断言从「已隐藏 1 条」改为状态条文案与 `data-mode` |

计量单位两页不同（写入点 / 子 TI 写入点 + 参数使用位置），所以文案由调用方算好再传，
宏里不猜——猜错就是新的假数字。

## 5. 测试

```bash
PYTHONPATH=src ./.venv/Scripts/python.exe -m pytest tests/test_export_scope_parity.py -q
# 11 passed, 1 warning

PYTHONPATH=src ./.venv/Scripts/python.exe -m pytest -q
# 1253 passed, 1 warning in 179.35s
```

三条新断言：

1. `business` 态：`data-mode="business"`、主文案「当前范围：1 条写入点」、说明「另有 1 条…未显示」、链接含 `system=1`；
2. `none` 态：`data-mode="none"`、文案「这个 TI 没有 } 前缀写入点」、**不含**「看全部」；
3. `all` 态：`data-mode="all"`、主文案变「2 条写入点」、链接含 `system=0`、不再出现「另有」。

断言抓的是渲染出来的 HTML（`<div class="scope-bar" data-mode="…">` 包裹的内容），
不是变量值——变量对而模板没渲染，是这类改动最容易出的错。

## 6. 剩余限制

1. **没有浏览器实测**：只验到 TestClient 输出的 HTML 结构与文案；
   三态配色、换行、暗色主题的实际观感没有截图确认。
2. 状态条只加在计算检查与子 TI 参数检查两页。血缘图、调用来源差异页仍用各自的
   `.scope-switch` 切换按钮，没有统一——它们的选择是「业务/系统/全部」三选一，
   与这里的二态开关语义不同，硬套会失真。
3. 文案里的数字依赖 `scope_view` 的账，若将来新增第三类范围（如「只含框架」），
   宏需要跟着扩展 `data-mode`。
