# 维度结构检查与大维度检索（2026-10-14）

## 1. 产品结果与范围

对应反馈 5，支柱 Reverse Engineer / Prove：维度入口从名称清单变为结构检查台。闭环为 Cube 维度名称 → 元素搜索 → 直接父子关系与原始权重 → 属性/子集定义 → 使用该维度的 Cube。

这有助于核对计算坐标、汇总权重与迁移边界。本轮不提供 Cube 数值切片、MDX 求值、全部层级浏览、元素属性值编辑、递归汇总计算或数值等价证明。

## 2. 检查到的代码与数据契约

- 原 `/dimensions` 只有名称分页，没有详情入口；名称使用 ILIKE，输入 `%` / `_` 会成为通配符。
- 现有 `dimensions` 表保存元素、属性定义、父子边及子集 JSON。`TM1Client.fetch_dimension` 只采集选中层级的元素名称/类型、边/权重、属性名称/类型及子集名称/表达式。
- `_get_hierarchy` 优先尝试同名层级，失败后取第一个层级；最终层级名称没有持久化。系统维度轻量模式可能只有元素字符串清单。
- 当前契约不能证明采集了全部层级、元素属性值或子集成员。空表达式也不能证明子集为空。

## 3. 实现与文件

- `store/dimensions.py`：在 DuckDB 内展开选中维度的 JSON，字面量搜索、原始下标排序、50 条分页；兼容字符串式元素，保留无效记录与未知类型。直接边保留负权重、零权重、缺失值、布尔值和未识别表达式，不补默认 1；按页批量检查端点是否有元素记录。超长权重明确截断且不判为已知数值。
- `api/app.py`：维度列表与详情、元素邻接筛选、子集原始位置选择、关联 Cube；来源指纹覆盖文件与 WAL，过期位置和请求中换源返回 409，不存在的维度/子集返回 404。Cube 结构名称链接到对应维度。
- `templates/dimensions.html`、`cube_view.html`、`static/workbench.css`：左右工作区，五个结构视图、全量名称搜索、分页、证据边界和 UNKNOWN；窄屏变为上下布局。
- `store/dimension_index.py`：大维度按需、后台建立当前维度的 SQLite 检索索引，沿用已有 TaskManager/ResultArtifact。模型指纹、维度名和索引版本共同隔离缓存；每批 1000 条，保留原始位置。检索端最多返回 50 条，直接上下级使用索引，不反复扫描完整元素 JSON。
- `tasks.py`：增加只读 `active` 查询，避免清理正在发布的索引文件对；原任务接口与生命周期保持兼容。
- `static/dimension-index.js`：显示真实阶段/条目计数，取消、重试、离页返回复用任务，完成后进入原筛选页。仅有实际计数时显示计数进度；阶段编号不当成总耗时百分比。
- 新增 `/api/dimensions/index`、`/api/dimensions/index/{task_id}` 与取消接口。大维度元素/边首次需要索引；只看较小的属性定义、子集或 Cube 关联时不强制等待索引。
- `tests/test_dimension_workspace.py`、`test_dimension_index.py`：结构事实、查询边界、资源预算与任务生命周期回归。

不增加依赖、不修改数据库模式或历史 JSON。代码可以通过还原本次提交回滚；派生索引可重建，不属于原模型。

## 4. 合成证据示例

`Example` 的直接边包含 `Total → Expense`，原始权重 `-1`，对应 `dimensions.edges[1]`；`Total → Disabled` 的权重为 `0`。选择 Expense 只显示其直接邻接记录，不生成递归值流或最终汇总值。

缺失权重显示 UNKNOWN；引用不存在的元素显示 PARTIAL。已有调用/依赖关系没有被解释为数值贡献。

动态子集原文保留 MDX 并明确未求值；静态子集空表达式显示“没有已保存的静态成员清单”。属性只展示已保存的名称与类型。历史字符串元素的类型保持 UNKNOWN。

## 6. 性能、安全与兼容性

原实现的风险不仅是返回行数：侧向展开 JSON 可能在数据库内部重复大字段。现已改成标量选取再展开，并用 256MB 数据库预算验证万级元素查询。另行验证十万级合成数据可在该预算下返回一页。

真实大维度还暴露出每次重新解析 JSON 的延迟，因此超过 50000 条的相关结构按需建立索引；索引建立一次遍历当前维度的四类记录，不构建全模型图。后续按索引分页，子串搜索仍可能扫描当前维度的搜索字段，并非恒定时间。

索引沿用单工作线程与有限队列，最多保留 16 条任务记录；派生结果缓存预算为 1GiB，旧缓存按现有 TaskManager 策略清理。缓存键是模型指纹与维度名的哈希，不能指定任意文件路径。损坏/缺失的派生文件对可重建；取消或失败的临时目录清理，源模型不写入。

首次建立大索引需要时间；取消在当前读取或索引操作结束后的检查点生效。服务重启丢失在途任务状态，但完整磁盘索引可以继续复用。多服务实例协调不在本轮范围。

旧 `/dimensions?q=...&page=...` 地址保持可用，新增选择与视图参数。名称搜索改为字面量；旧 CLI、采集器及模型表结构不变。

## 7. UNKNOWN 与限制

- 已保存的单层级结构不能代表全部层级，层级名称仍未知；本轮没有联网补采。
- 没有完整元素属性值或子集成员，不将 MDX 定义当作成员结果。
- 直接边不是运行时计算证据，不递归展开循环、推导汇总值或解释财务目的。
- 记录下标与文件指纹用于定位和失效判断，不是完整快照版本控制或内容级证明。
- 超长 MDX 展示前 8000 字符，异常权重原文前 240 字符；明确标注截断与未知。
- 更新源码不会自动更新已有 exe；完整 Arc 式数值切面浏览仍需新的数据采集与权限契约。

## 8. 下一项建议
