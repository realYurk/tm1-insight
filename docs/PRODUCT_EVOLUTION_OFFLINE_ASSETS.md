# TM1 Insight 产品演进：离线资产提炼与可验证重构

状态：产品决策与实施路线，2026-11-03。本文不是已交付功能清单。产品宪法及证据约束优先；现有代码和数据的安全边界继续有效。

## 1. 产品结果

让开发者把已有模型的已采集资料安全带到离线环境，快速回答：系统有哪些重要对象？某个结果由什么形成？功能需要哪些维度、输入、处理、规则与依赖？重建时还缺什么？资产推荐提供可解释候选；业务重要性、意图与运行结果不能凭静态代码自动认定。

目标用户：接手陌生模型的开发者、负责重构的架构师、需要理解业务流程的使用者。核心闭环：采集或导入 → 本地检索 → 候选资产发现 → 选定功能范围 → 确认结构与形成 → 人工补充设计决策 → 导出离线包 → 独立复核与验证。

## 2. 审计结论与待验证假设

- 源码查看同步构建调用树和查询/分析变量；大源码的多段高亮和搜索可能增加首屏或输入延迟。须用当前版本在真实机器和合成大模型上分层计时，不能把潜在风险当作已测瓶颈。
- 相同写入/来源在多个页面和报告重复投影；此前曾修复来源确认不一致。应核对事实生产者与展示组件，不把多入口直接视为重复引擎。
- `architecture.js` 已使用 URL 和 sessionStorage 保存部分上下文，不能断言完全没有持久化；刷新、返回、服务重启、模型切换和过期任务的具体故障须复现。
- `workbench_export.py` 的维度摘要含每类前 25 项采样，不能作为完整维度恢复证明；已采集信息也不等于完整服务器备份。
- 现有 Cube、TI、Chore、血缘、MDX 等具备具体使用价值；各自覆盖和质量须实测。维度浏览、代码生成、影响分析可服务重构，不能仅凭不符合资产盘点场景就判为无用或删除。旧入口和用户数据保留。
- 市场工具的具体能力和优劣尚未做独立核实；不把用户提供的竞品描述当成已验证事实。借鉴方向是快速浏览、清晰可视化、可检索文档、离线交接与可追溯分析，避免复制品牌或未经许可资源。

## 3. 面向用户的产品结构

保留模型浏览、数据血缘、业务架构和代码生成等既有入口，按用户任务整合：检索对象、解释形成、整理功能、导出交接。Cube 页面回答结构和写入；血缘画布回答对象之间的可见关系；功能工作流回答输入到输出及边界；证据和诊断按需展开。相同写入卡片、Rule 摘要、搜索和源码组件复用，不增加平行语义引擎。

首页以检索与已有 MDX 反查等高价值任务为入口。未知只在影响当前结论时合并展示：缺什么、影响哪些位置、可怎样补充。隐藏技术噪音不等于删除缺失信息。探索操作只改变临时视图，不触发保存提示；真正持久化的人工设计记录独立保存。

## 4. 可解释的资产发现

在现有索引上提供候选排序及筛选：例如被多少独立 TI 读取或写入、多少 Rule 引用、Chore 调度、已采集前端引用、属于用户选定功能边界。每项同时展示数据来源、采集覆盖和统计范围。结构中心性、引用数量和代码复杂度只是技术信号，不证明业务价值；未知、过期和未采集不能计作零。用户可确认核心资产、调整权重或关闭排序，并可查看全部结果。不得以排名截断真实依赖或以对象命名自动判断业务意义。

## 5. 离线资料与设计包契约

区分三种产物：
1. 阅读摘要：功能流程、关键对象、切面、人工说明和关键缺口。
2. 离线模型/功能设计包：已采集定义、源码、关系、证据、功能边界、清单、版本、校验、缺失及截断；离线可检索。必要时支持增量、分页及流式导出。
3. 服务器恢复备份：另有独立要求，现有分析包不得声称具备此能力。

明确成员、层级、权重、属性、子集、View、数据源变量、TI、Rule、Feeder 和 Chore 的记录状态及完整程度；人工注释与源码事实分离。企业源码、路径和元数据可能敏感；默认排除凭据和业务单元格，用户控制导出和分享。导入先校验 schema、校验和、文件路径及资源预算，在独立位置原子落地，失败不覆盖原模型；软件与数据分离。动态路径、配置和模型外部系统作为依赖保留，不伪造值。

## 6. 多维设计经验

针对明确功能，记录结果粒度、Cube 维度顺序、层级与权重、成员映射、TI/Rule 分工、清空与累加、调度、外部接口、重跑和验证方法。系统填入有证据的事实，用户补充设计原因和取舍并明确确认；只在有具体案例、适用边界、反例和验证时沉淀可复用模式。不能以变量名或对象名自动生成业务解释。

## 7. 分阶段交付与门槛

### 阶段 0：基线和职责盘点
测 TI 冷/热首屏、SQL 数、源码解析、响应体积、浏览器渲染与搜索；构造普通、长源码、深调用、高扇入和循环合成模型。记录设备、样本、P50/P95 与误差。逐条映射页面、API、事实生产者、缓存和导出；复现状态丢失后定位具体路径。验收：可重现测量、重复职责清单及有证据的优先级；未测项目明确列出。

### 阶段 1：源码查看性能和状态可靠性
源码和必要元数据先返回，调用树、计算和非当前 Section 按需加载；限制节点及并发，长文本分批显示，保证复制、搜索、行号和源码定位。恢复模型限定的 URL/会话状态，失效任务可重试。建议目标：普通 TI 可读首屏 P95 ≤ 1 秒、热访问 ≤ 300 ms；先定义规模和设备，实测后调整，不以隐藏源码换成绩。验收：端到端前后对比、浏览器交互、刷新/切模型/取消重开和全量回归。

### 阶段 2：一致的事实与共享组件
核对 Cube、血缘、架构、Workflow、Markdown、Mermaid、JSON 的对象身份、方向、证据和确认状态，优先复用现有解析与存储。统一写入卡、Rule 卡、搜索和源码组件；旧 API 保持兼容。验收：常量、已确认 CellGet、共同读写、动态 Cube、未知函数、条件、VIEW 缺字段、Rule、Feeder 和自环合成正反例跨视图一致，缓存随源码与版本变化失效。

### 阶段 3：离线模型资料包
在现有 Snapshot 与 Portable 基础上提供明确范围、版本、校验与完整性清单，支持有界打包和独立导入。验收：隔离且断网的新环境中可打开、检索、查看源码、维度、血缘及缺失信息；损坏、旧版、路径穿越、取消和失败不破坏现有数据。记录包大小、耗时、峰值内存和采样限制。

### 阶段 4：功能提炼与交接
从 Cube/Measure/MDX/TI 选择入口，沿证据发现候选，人工确认边界，整理维度、输入、处理、Rule、输出、外部依赖及缺口，导出人类阅读版和结构化版。不得用前缀限定全部依赖，也不得把候选标为完整。验收：独立开发者在离线环境找到关键写入、引用及重建所需对象，正确识别未知和遗漏。

### 阶段 5：经验与可验证重构
支持人工确认设计决策、结构模式和针对功能的合成测试、结果比较及差异证据；可导出目标无关契约。验收：独立人员能够复核至少一个功能的粒度、设计取舍、源代码证据和验证边界；静态解析不能宣称等价。未经单独授权不引入业务单元格、执行 TI 或生成部署代码。

### 阶段 6：长期产品质量
覆盖 Windows Portable 安装及升级、旧包兼容、异常恢复、可访问性、本地隐私、文档和支持。设置代表性大型模型冷/热性能、交互延迟、内存、取消延迟的持续回归，并定期对竞品公开资料核实后更新对比。完成两名未参与实现者的任务验收，记录时间、步骤、误判与失败原因；缺参与者标待完成。

## 8. 当前建议和非目标

下一项先复现 TI 页面性能并交付源码优先加载，再推进一致性与离线包。每阶段先评估可复用能力，按最小闭环交付、专项与完整回归。冻结无证据业务标签、全自动重要性判断、平行解析器、新画布建模、默认远程服务和以导出数量代替交接质量。严禁把任何推荐排序或截图包装成业务专家确认。
