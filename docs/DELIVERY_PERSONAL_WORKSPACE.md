# 明亮的个人工作台与任务导航（2026-10-14）

## 1. 产品结果与支柱

解决用户明确反馈：配色阴暗、单人使用却要求评审人、多个分析入口用途混乱。推进 Reverse Engineer / Prove 的可用性与 M6：按实际任务进入，优先看计算证据，经验由本人整理，不存在审批流程。

范围：全站配色与主题默认值、导航分组、五个页面的输入/输出说明、学习结果默认顺序、个人经验保存约束。非目标：登录系统、多人权限、自动业务解释、运行时验证或完整模块提取。

验收：明亮主题默认生效；功能梳理先展示 TI；改动影响清楚区分两个方向；本人不填写评审人也能整理经验；旧记录与历史不被覆盖；验证状态仍要求测试记录；原分析/导出路由可用。

## 2. 检查到的实际实现

- `base.html` 原将学习、经验、图谱、影响和导出型工具平铺在「分析」下；旧主题记忆可能继续应用暗色。
- `learn.js` 原默认打开通用教材章节，输入框默认 `*`，实际 TI 与公式位于第三个分类；完整覆盖账本和完成进度始终占据首屏。
- `learning/experience.py:update` 原把 reviewer 作为 reviewed / validated 的必填字段，没有登录或审批执行机制。
- `api/experience.py` 原保存时把未提交字段的默认空值也写入，隐藏旧字段后可能覆盖历史信息。
- `impact.html` 的依赖方向名称含 Downstream / Upstream，读起来容易与数据传播混淆。底层仍是结构依赖可达路径。

## 3. 实现与文件

- `static/workbench.css`：白色侧栏、浅蓝内容背景、清晰蓝色选中态与按钮；深色主题保留为手动选项。主要文字对比度实测充足，未改变代码高亮规则。
- `base.html`：找逻辑 / 查影响 / 留经验与复用 / 系统与数据；对象关系图、证据包导出、快照状态收进「更多工具」，访问这些路由时自动展开。旧菜单名称调整，路由不变。
- `templates/task_help.html` 及 learn / impact / experience / graph / knowledge：说明什么时候用、输入什么、得到什么、下一步去哪；提供相关任务链接。
- `templates/learn.html`、`static/learn.js`：默认打开关键 TI，相关 Cube 和待核对事项为主要分类；参考方法等收起。输入不再默认整模型；覆盖账本和引用细节按需展开，任务完成后收起进度区。乘除信号明确称为计算线索。
- `templates/experience.html`、`static/experience.js`：待整理 / 已整理 / 已记录验证 / 暂不复用；删除评审人输入与审批措辞，保留修改原因、版本历史和验证记录；分摊方案比较作为可展开辅助工具。
- `learning/experience.py`：已整理不再要求 reviewer，仍要求问题、适用条件和限制；已记录验证仍要求验证笔记，模型变更后的旧证据保护保留。
- `api/experience.py`：仅更新实际提交字段，兼容旧 reviewer 字段但不要求填写，不覆盖旧作者信息或未提交的验证笔记。
- `workbench_home.html`：按理解、修改、记录三个目的提供入口。`impact.html` 使用“它依赖谁 / 谁依赖它”，将自身引用标明；保留原路径，不更改关系引擎。
- `tests/test_experience.py`：无 reviewer 整理、验证笔记要求、失败不增版本、源库只读、旧字段及历史保留。

主题偏好使用新键 `tm1-theme-v2`，旧键不删除。新版第一次打开默认明亮，用户仍可主动切换并保存新偏好。

## 4. 用户任务与证据示例

| 想做什么 | 入口 | 输入与结果 |
|---|---|---|
| 看懂某块计算 | 功能梳理 → 关键 TI → 计算检查 | 名称关键词；定位实际 TI、表达式、坐标与源码位置 |
| 修改前查依赖 | 改动影响 | 准确的 TI / Cube 名；分开查看依赖对象与结构依赖方，作为回归检查范围 |
| 保存自己的方法 | 我的经验 | 从实际 TI 保存线索，再记录业务问题、适用条件、限制与自己的测试结果 |
| 看关系形状 | 更多工具 → 对象关系图 | 指定 TI；查看已有引用和调用观察，不等于运行时值流 |
| 保存分析材料 | 更多工具 → 证据包导出 | 指定范围；导出私有证据材料，不替代功能解释 |

合成 Demo：搜索 `Load` 后直接看到 Load_Sales 和 Sales 的已解析写入引用；进入计算检查时未知字段保持 UNKNOWN。从该 TI 保存线索，本人不填写评审人即可保存第 2 版“已整理”，第 1 版仍在历史中。没有测试笔记不能标记“已记录验证”。

## 6. 兼容、数据安全与性能

不改模型数据库或经验库结构，不迁移/删除旧记录，不增加依赖。保留原状态值 candidate / reviewed / validated / deprecated 与 API 旧字段，界面显示个人整理含义。历史信息仍可备份。

页面引导为静态服务端模板，不触发新的模型扫描。学习任务、分页、缓存、取消和作用域接口保留；整模型分析仍可显式输入 `*`，不再作为默认值。

原 8766 端口没有服务监听，已在原地址以后台隐藏窗口启动新版，仅绑定 127.0.0.1，并关闭访问 URL 日志。先确认已选真实离线来源，启动后核对来源一致。该服务留给用户继续使用；独立合成验证服务和页面结束后关闭。

## 7. UNKNOWN 与限制

没有增加登录或审批机制；“已记录验证”仍是用户自行记录，不是软件执行证明。来源变更提示、版本冲突和验证笔记要求保留，以免把旧证据当成新结果。

本轮不新增语义推断。改动影响是结构范围，不能证明金额影响；对象关系图不是执行图；参考设计方法不是当前模型已验证的业务算法。运行时和迁移等价边界不变。

## 8. 下一步建议

继续让“功能梳理”的结果围绕一个明确入口形成可核对的功能范围：参数、来源、计算、结果、外部边界和未知项集中展示。沿现有单 TI / 单次调用检查复用证据，不重新堆叠通用教材和对象规模卡片。
