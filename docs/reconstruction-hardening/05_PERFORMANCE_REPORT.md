# 05 性能测量

Windows 11 22621，Intel Core i5-12490F（6 核 / 12 线程），15.9 GiB 内存，Python 3.13.12；内存中构造纯合成索引，未访问企业模型。每组 1000/3000/5000 Cube 和同数 TI，462 条索引边，其中一个无关 TI 有 230 读 × 230 写，目标 TI 各有一次读写。

| 规模 Cube / TI | 首次查询秒 | 同进程重复两次秒 | tracemalloc 峰值 MiB |
|---|---:|---:|---:|
| 1000 / 1000 | 0.0076 | 0.0034 / 0.0041 | 0.08 |
| 3000 / 3000 | 0.0047 | 0.0045 / 0.0040 | 0.06 |
| 5000 / 5000 | 0.0052 | 0.0047 / 0.0041 | 0.06 |

这是纯函数计时，构造索引之前的时间和内存未计；重复调用不是持久化缓存命中，tracemalloc 不是进程总 RSS。旧实现对 3000 反例查询约 0.726 秒并丢失目标，新实现返回 1 条候选。

未测磁盘 DuckDB 冷/热缓存、首屏、取消、Rule 密集、多线程、布局耗时及帧率；不据此声明生产性能。局部高扇出仍可能触及 50000 候选预算，时间和证据规模有风险。

## 隔离 DuckDB 内存库

同设备在 `:memory:` 中建立合成对象与关系表，计时从索引构建开始；每次仅查询独立目标。下表为冷构建索引和随后三次查询，峰值仅为该阶段 tracemalloc，不包括建表填充或 DuckDB 原生分配。

| Cube / TI | 冷索引秒 | 首查秒 | 重复两次秒 | Python 峰值 MiB |
|---|---:|---:|---|---:|
| 1000 / 1000 | 0.084 | 0.0055 | 0.0043 / 0.0033 | 1.35 |
| 3000 / 3000 | 0.157 | 0.0042 | 0.0035 / 0.0028 | 3.03 |
| 5000 / 5000 | 0.227 | 0.0040 | 0.0033 / 0.0042 | 4.54 |

内存数据库不是磁盘冷缓存；仍未测大量 Rule、调用、进程 RSS、浏览器帧率、取消延迟及高扇入目标本身的最大预算。
