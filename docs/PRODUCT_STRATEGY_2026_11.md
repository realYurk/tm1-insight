# TM1 Insight 产品战略修订：从「证据审查工具」到「资产提炼产品」

状态：2026-11-03 · 绑定方向，与 `PRODUCT_CONSTITUTION.md` 同步生效。
作者：产品负责人视角的重构方案，不是已交付功能清单。

---

## 0. 一句话结论

现有产品**证据严谨、视角发散**：它能证明"这条线索有源码支持"，但不能回答"这个模型里什么是核心资产、它在干什么、怎么实现的"。
要变成后者，需要**做减法 + 换视角**，而不是继续叠加功能。

本轮已经动手的第一刀：新增「资产地图」，并把"资产视角"接进数据血缘——**原有血缘画布一张不留地保留**。

## 1. 六条批评 → 六个结构缺陷 → 六条对策

| # | 现象（用户/评审原话） | 根因（不是 bug，是设计） | 对策（本轮或后续阶段） |
|---|---|---|---|
| 1 | 产品被当成"资产提炼工具"用，但它只承诺"迁移证据" | 产品契约只承诺**可复查**，没承诺**可行动**；输出形态天生是证据包 | **双层输出契约**：第一层给结论（人读、可带走、写清边界），第二层才是证据（按需展开）。归纳允许存在，但必须标注依据、覆盖范围与不确定项 |
| 2 | 入口双轨制：主导航一套，上下文触发另一套 | 导航按**功能模块**组织，用户按**任务**组织 | **单一入口原则**：一个功能只有一个正式入口；其余路径一律是深链，且落到同一状态（P1/P5） |
| 3 | 画布刷新丢状态，从业务架构搜索再刷新就跑出别的画布 | 画布状态存在 JS 内存 / sessionStorage，没进 URL | **URL 即状态**：模型指纹 + 对象 + 筛选 + 视图全部编码进 URL，服务端可原样重放（本轮在 `/atlas` 落地，P1 覆盖画布） |
| 4 | 只有 TI / Cube / Chore / 血缘"能用" | 把**分析引擎**当**产品功能**：引擎能跑就上导航 | **功能准入门槛**（见 §4）：四条硬指标不达标的功能不进一级导航，进"实验/高级"或直接下架 |
| 5 | PARTIAL / UNKNOWN / 待核对 高频出现，认知成本高 | 把**证据完整性**直接当成**界面信息密度** | **未知按影响面分级**：只在与当前结论冲突时出现；其余收进"证据与边界"，并给一句人话解释 |
| 6 | 导出的是机器可复查格式，不是能拿去汇报的摘要 | 导出模板为机器设计 | **人读版强制存在**：结论 / 关键对象 / 依据 / 缺口 / 下一步，固定五段式（本轮 `/api/atlas/export` 已按此落地） |

## 2. 竞品该吸收什么、不该吸收什么

> 说明：以下为**方向性借鉴**，不是逐条核实过的能力对比。任何具体功能在实现前都要用公开资料复核，不得把描述当事实（沿用宪法「不伪造能力」约束）。

| 参照 | 它的强项 | 吸收 | 不吸收 |
|---|---|---|---|
| Omni（TM1 ERD 类） | 打开即见完整实体关系图、响应快 | **"一眼看到全局结构"**：用有界聚合（按域/前缀/连接度）实现，而不是 3000 节点画布 | 只有图没有证据、无法回答"谁写的/怎么算的" |
| QUBEdocs / SPACE / TM1 Dokutool | 自动生成交互式文档，对象→图表映射 | **"每个核心对象一页讲清楚"**（P4）：它是什么、谁写、谁读、怎么算、影响谁 | "导出即完成"的文档观；文档不等于理解 |
| tm1craft-client | 一条命令抓取关键对象交给服务端 | **CLI + 打包带走**：资产清单一键导出，离线可读 | 依赖远端服务、需联网 |
| dbt lineage / Atlan 类资产目录 | 搜索优先、资产目录是主视图、影响面清晰 | **资产目录作为第一入口**（本轮 `/atlas`）、影响面在对象页就地展开 | 通用元数据平台的重量级治理流程 |
| 现有 tm1-insight 自身 | 静态证据链、离线、只读 | **保留**：证据是差异化护城河，只是不该站在第一排 | 让证据成为唯一的输出形态 |

**定位一句话**：比文档工具更懂"计算与依赖"，比 ERD 工具更懂"证据与边界"，比资产目录更懂"TM1 语义"。

## 3. 新信息架构（IA）

一级导航只保留 **5 个任务入口**，其余一律下沉。用户不再需要记"这个功能藏在哪个 tab"。

```
工作台        /
资产地图      /atlas           ← 我有什么？什么重要？（本轮新增）
数据血缘      /graph           ← 数据怎么流动？（原画布保留，加资产视角条）
业务架构      /architecture    ← 一条业务链怎么实现？（P1 收敛为单一视图栈）
模型浏览      /cubes /processes /dimensions /chores  ← 合并为一组，不再是四个独立入口
──────────  工具（二级，不再新增一级入口）
代码生成 / 快照对比 / 前端资产 / 影响分析 / 证据包 / 经验
```

三条硬规则：

1. **一级入口 ≤ 5 个**。想加功能，先在现有入口里找位置；找不到就不做。
2. **代码生成不再是一级入口**。它是开发辅助，不是资产理解的主路径。
3. **深链必须落到同一状态**：从资产地图点进血缘、从 Cube 页点进架构，得到的画布与直接打开该 URL 完全一致。

---

## 4. 功能准入门槛（Feature Gate）

任何新功能，四条全过才允许出现在一级导航：

1. **有唯一答案**：能用一句话说清"它回答了哪个问题"，且答案不是"更多线索"。
2. **输出可消费**：有人读版输出，评审/交接时不需要二次加工。
3. **边界可陈述**：明确说出它**证明不了**什么，且这句话出现在界面上，不是藏在文档里。
4. **可被度量**：有明确的验收数据（耗时、点击数、误判率），不达标就回退。

不满足的功能：留在"工具"，或直接下架。**下架是合法产品动作**（P5 执行）。

## 5. 分阶段路线（P0–P5）

每阶段都有"验收门"，不达标不进入下一阶段。阶段内先交付最小闭环，再扩展。

### P0 · 立住资产视角（本轮，已交付）

- **目标**：让用户第一次打开产品就能回答"这个模型里什么在承载加工"。
- **交付**：
  - `/atlas` 资产地图：Cube / TI / Dimension / Chore 四类资产的信号化清单，排序、搜索、分页、URL 即状态。
  - 六项透明信号（写入 TI、读取 TI、Rule 引用、调度链、前端页面、含 Rule），权重写在代码里可改，界面可核对。
  - 覆盖缺口面板：无写入方 Cube、无前端引用 Cube —— 明确"没记录 ≠ 没用"。
  - 人读导出：`/api/atlas/export` 生成可直接进评审的 Markdown 清单。
  - 数据血缘页顶部"资产视角"信息条（原画布未改动一行逻辑）。
  - 宪法修订：资产提炼优先、导航收敛、单一入口。
- **验收门**：
  - 3660 Cube 的真实模型上 `/atlas` 首屏 < 300 ms（实测 0.11 s）。
  - 任一对象从"资产地图"到"看到它的形成" ≤ 2 次点击。
  - 导出 Markdown 含：规模、口径、信号说明、清单、缺口、免责边界。
  - `tests/test_atlas.py` 全绿；相关回归（导航、血缘呈现）无回归。
- **不做什么**：不做全自动"业务重要性"评级；不引入 LLM；不动血缘画布。

### P1 · 业务架构收敛为单一视图栈（下一步，最高优先级）

- **问题**：现在同时存在两套 UI（`functional_flow` 老栈 + `workbench` 画布栈），入口、状态、术语都不一致——这是"很乱"的直接来源。
- **动作**：
  1. 二选一作为**唯一**架构视图，另一套降级为"画布模式"开关（同一 URL、同一状态）。
  2. 把"流程总览 / 数据模型 / 数据形成"三个视图的切换做成显式 Tab，状态进 URL（`view`、`name`、`kind`）。
  3. 架构页首屏先给**一条链的答案**：入口 → 输入 → 处理 → 输出 → 缺口，一段话 + 一张小图；证据默认折叠。
  4. 删除重复入口：`/architecture?view=workbench` 不再作为独立入口出现。
- **验收门**：
  - 同一对象从 4 条不同路径进入，URL 与首屏内容完全一致（写自动化断言）。
  - 刷新、后退、切换模型后画布节点/展开/聚焦全部恢复；恢复失败时有明确提示而不是空白。
  - 首屏"一段话答案"对 5 个抽样对象人工验收通过（找 2 名未参与实现者）。
- **风险**：两套栈共享部分 API，合并时可能触发状态不一致。用"先合并入口、后合并渲染"的两步走降低风险。

### P2 · 资产视角贯通（血缘 / 架构 / 对象页）

- **动作**：
  1. 把资产条扩展到 TI、Dimension、Chore 页（复用 `atlas.position`）。
  2. 允许用户**人工确认**"这是核心资产"，写入本地工作区（与静态信号分离，可撤销）。
  3. 资产清单支持按"人工确认 / 未确认 / 有缺口"筛选。
  4. 交接包 v1：资产清单 + 关键对象源码 + 缺口清单 + 人工确认记录，一个 ZIP 带走。
- **验收门**：独立开发者在离线环境用交接包回答"这个模型的核心加工链是什么"，不需要打开原系统。
- **风险**：人工确认数据不能与快照版本混用，必须按模型指纹隔离。

### P3 · 全模型结构总览（Omni 式，但有界）

- **动作**：以"域/前缀 + 连接度"聚合出全局结构图，节点是**簇**不是单个 Cube；点开簇才展开。
- **验收门**：3000+ Cube 的模型上，总览首屏 < 1 s，节点数 ≤ 80，任意对象 2 次点击可达。
- **不做什么**：不渲染 3000 节点画布（宪法仍禁止"把大模型摊平成不可读画布"）。

### P4 · 可读文档生成（QUBEdocs 式，但带证据）

- **动作**：对每个核心对象生成一页：它是什么、谁写、谁读、怎么算、影响谁、缺什么。批量导出可按资产清单范围选择。
- **验收门**：一页内容能通过"新人 10 分钟读懂"测试；每段结论有源码定位。
- **风险**：容易退化成"生成一堆没人看的文档"——所以只对**用户选中的对象**生成，不做全模型批量输出。

### P5 · 减法与收敛（每半年一次）

- **动作**：用 §4 的四条门槛复审全部功能；不达标的移到"工具"或下架；导航定稿；性能与可访问性回归。
- **验收门**：一级入口 ≤ 5；"功能坟墓"清单为空；每个入口有明确 owner 与验收数据。

## 6. 度量：怎么判断"变好了"

| 指标 | 现状（估） | 目标 |
|---|---|---|
| 打开产品到"看懂一个对象"的点击数 | 4–6（跳转 + 搜索 + 展开） | ≤ 3 |
| `/atlas` 首屏 P95（3660 Cube） | 0.11 s（实测） | ≤ 0.3 s |
| 导出物可直接进评审的比例 | 低（需二次加工） | 100%（五段式模板） |
| 一级导航入口数 | 5 + 隐藏组 + 二级路径 | 5，且无隐藏组 |
| 同一功能入口数 | 2–3 | 1 |
| 刷新后视图丢失的页面数 | ≥ 2 | 0 |

## 7. 明确不做（反向清单）

1. 不做第二个语义引擎（复用现有 parser / resolver / store）。
2. 不做全自动业务重要性判断；排名必须可解释、可关闭、可人工覆盖。
3. 不新增一级导航入口。
4. 不在画布上堆三千个节点。
5. 不引入 LLM / RAG / 向量库 / 外部 AI 服务。
6. 不为了"看起来完整"而伪造粒度、公式、执行顺序或业务含义。

## 8. 与宪法的关系

本文与 `PRODUCT_CONSTITUTION.md` 的「资产提炼优先 — 绑定方向」章节配套：

- 宪法定义**不可违反的边界**（证据诚实、只读、离线、无 LLM）。
- 本文定义**产品形态与优先级**（五入口、双层输出、功能门槛、阶段路线）。
- 冲突时以宪法为准；宪法未覆盖的形态问题以本文为准，并在实施后回写宪法。
