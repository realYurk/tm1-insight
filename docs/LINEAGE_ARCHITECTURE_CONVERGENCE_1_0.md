# 数据血缘与业务架构：收敛式重构 1.0

日期：2026-10-26。开发基线 `df39297`，包含审查基线 `a514aaa`。本文件记录信息架构、页面草图、交互、第一阶段实现和验收边界；不是全面完成声明。

## 1. 信息架构决策

| 现有入口 | 职责 | 默认信息 | 二级信息 |
|---|---|---|---|
| 数据血缘 / Cube | 查看直接上下游 Cube | Cube 图、候选或 Rule 关系表、右侧关系摘要 | 逐写入切面、表达式、条件、原始证据 |
| 数据血缘 / TI | 查看调用方与被调用方 | 纯 TI 调用图、选中程序读写与参数摘要 | 调用参数与条件、逐 CellGet/CellPut、行变量与技术诊断 |
| 业务架构 | 看局部模块输入、处理、结果 | A 流程图、B 对象与作用、C 动作与切面、D 下钻入口 | 模型结构、形成分析、统一关系、调度、技术辅助与完整导出 |

Cube 与 TI 使用同一模式选择器，切换时不把 Cube 名当 TI 名继续查询。保留旧 `/graph?cube=...`、`/graph?ti=...`、架构及 Workflow 路由。没有增加顶层导航，没有删除设计实现或历史草稿。

架构默认已有 `functional_flow` 路由，本轮调整该页的阅读顺序和技术入口，而非再造一份架构。`view=workbench` 保持只读索引辅助入口；不增强设计、保存与拖线建模。

## 3. 交互流程

1. 选择 Cube 或 TI → 输入对象 → 自动补全 → 分析。两个模式分别查询既有端点。
2. Cube 图中的实线 Rule 引用与虚线共同读写候选分别标注。TI 只是候选边的机制，不作为 Cube 主节点。
3. 点击连线或表中“查看详情” → 右侧显示机制、关键固定坐标与写入方式 → 按需打开某写入点 → 再展开原始证据。
4. TI 图显示直接 Caller 索引与已解析下游调用。索引入口明确标“索引调用入口”，不冒充源码确认；节点点击可重新聚焦程序。动态调用保留在详情，不能补造目标节点。
5. 业务架构先看流程，再看对象、动作；对象或动作详情能跳转血缘及源码。复杂技术视图的按钮统一收进折叠入口。
6. 退出查看页面不引入保存行为；本轮不增加 beforeunload、工作区保存或设计端点调用。
7. 摘要与技术导出保留当前分析范围；未分析、部分失败和预算截断不包装成完整结果。

输入、装载、计算、结果、输出是理解模板，不是自动业务分类规则。已有证据不能证明某对象是 Reporting、Allocation 或外部接口时，不按名称套用层级，不编造运行顺序。

### 保留并完成的 G1 投影工作

本轮接手时存在上一条任务尚未验收的 G1 文件，均保留。新增的 `formation_answer.py`、`api/workbench.py` 两个只读端点、`formation-answer.js` 和 `tests/test_formation_answer.py` 继续组成轻量展示投影。

- `GET /api/workbench/formation-plan`：Snapshot、目标 Cube、TI 预算；从目标写入索引找直接写入者，另含自身 Rule，不要求先有源 Cube。
- `GET /api/workbench/formation-item`：Snapshot、目标、TI/Rule、可选维度/固定成员；复用现有 Calculation 或 Rule 分析，返回 `cube-formation-answer-1`。
- 结果保留独立写入、固定/动态/未确认坐标、表达式、源值引用、条件、源码位置、共享根因与预算。常量与参数表达式单列，不要求有源 Cube。
- 切面只排除“已确认固定坐标不匹配”的项；动态坐标、缺少区域归属时标可能匹配，不声称匹配具体单元格。无切面时是区域概览。
- 单 TI 250k 源码预算（复用 Workflow 上限）、最多80目标写入；Rule 256k源码、最多80规则；客户端串行分析，保留成功项并允许取消重试。单项服务端计算仍是同步有限任务，客户端取消不意味着已中断正在执行的 Python 分析。
- 修复自测中“读取坐标包含参数，导致读取表达式被归为参数写入”的投影分类错误；不修改底层值依赖规则。
- 修复浏览器中把通用静态限制误当预算截断的展示错误；真正的预算诊断单独记录。

任务状态与证据状态分开：完成请求不等于完整理解。常量写入的“已确认”指静态表达式；始终 `runtime_verified=false`。新增投影不改变旧 API 字段或数据库 Schema。

## 5. 分阶段计划与停止条件

### 第一阶段：本轮最小落地

模式明确、主图区分对象、默认流程总览、右侧摘要、技术折叠、取消重试、原导出与路由兼容。用独立合成模型跑浏览器与回归。以本文件验收记录为准，不以截图存在宣称所有要求完成。

### 第二阶段：交互与信息密度

- 在现有画布/视图上统一 Cube 图标与 TI 卡片，不再另建画布。验证缩放时图标固定尺寸需求；本轮仅保持 Mermaid 的等比缩放，尚未实现屏幕像素固定的 Cube 图标。
- TI 邻居卡片按需获得读/写/调统计；本轮统计只显示当前选中 TI，不补造其他节点数据。
- 将关系摘要从计数进一步收敛成相同条件、表达式、写入方式下的切面组；不能合并不同条件或累加/覆盖。
- 为大扇入提供显式展开/分页与有界缓存；当前超24节点/30关系图回退表格，不画巨大图。
- 优化摘要导出：Cube 索引摘要、详细研究报告、形成 JSON 目前仍是不同深度，后续统一同一展示投影。禁止为此开发新语义引擎。

### 第三阶段：独立开发者验收

邀请至少两位未参与实现的开发者，分别查找：目标写入、常量与无关读取、动态参数、NativeView 来源、缺少 Variables 的真实阻塞、Rule 来源、取消重开与导出。记录准确性、耗时、操作次数、误判候选为值流、失败原因。未完成不能宣称整体可用性或 G1 最终通过。
