# TM1 Insight 产品契约

状态：产品方向与验收契约。本文中未来能力不等于当前版本已经实现。

## 产品要解决的长期问题

为 TM1 开发者和独立咨询顾问提供本地的项目理解、工程证据、经验积累和迁移准备能力。
软件的每项重要结论都必须能够回答：依据是什么、适用于什么情况、有哪些未解决问题。
产品分析不依赖 AI、网络知识检索、向量数据库或云服务。

核心工作路径：选择客户项目 → 选择模型快照 → 限定功能范围 → 查证据 → 比较实现 → 形成经验包 → 验证复用。

## 不可突破的边界

1. 客户数据、账号密码、内部地址、业务代码、快照、日志、报表及包含它们的截图，不进入 GitHub、公开发行包或其他互联网空间。
2. GitHub 仅承载产品源码、公开文档、虚构测试与无客户内容的程序包。
3. 产品不自动上传、不内置外部 AI、不进行遥测。诊断统计仅保存在本机。
4. 采集默认只读。分析不会执行 TI、修改 TM1 对象或回写单元格。
5. 导出始终为本地私有文件；脱敏、抽象和生成经验包都不构成发布或转交授权。
6. 客户项目分别保存。跨项目复用之前必须保留授权范围和来源约束；企业名称、对象名称、数据值和原始代码不自动进入公共模式目录。
7. 发布采用白名单和敏感内容检查。`.gitignore` 不是唯一保护措施。

## 经验包应当是什么

经验包是有版本、有证据、有适用边界的工程记录。仅保存源码或操作关键词不足以成为经验。

每个包包括：

- 来源：本地项目标识、快照内容指纹、提取器版本、提取范围、证据引用及知识使用权限。
- 问题：要解决的工程问题、输入输出、维度与粒度、业务约束、外部依赖。
- 实现：公式、条件、控制流程、参数传播、读写切片、执行顺序与副作用。
- 评价：正确性验证、适用前提、性能测试环境、维护成本、失败情形、已知限制。
- 替代方式：什么情况下使用另一种结构，以及更换结构需要满足的条件。
- 生命周期：candidate → reviewed → validated → deprecated；记录评审人与变更原因。

三层信息严格区分：源代码/关系事实、确定性分析形成的观察、由人确认的工程判断。
软件保留 UNKNOWN 和 unresolved，并将未解析部分显示在结果附近。

## 不使用 AI，如何回答“哪种分摊实现更合适”

建立有版本的工程模式目录，以及公开可解释的适用规则。目录最初来自人工整理的工程知识；项目提取结果提供匹配证据。
重复出现和命名相似只能成为调查线索，不构成质量证明。

用户描述需求时使用结构化字段：

- 来源、目标、驱动所在的维度与粒度；固定比例或动态驱动；单级或多级分摊。
- 数据规模与稀疏程度、更新频率、计算窗口、是否需要在线即算。
- 版本/期间隔离、是否需要审计、并发与重跑要求。
- 零驱动、缺失驱动、负数、舍入和尾差处理规则。

匹配流程：先检查必需条件和禁止条件，再展示适用方案及各项取舍。不用一个不透明的总分掩盖冲突。
结果应包含“匹配的证据、未满足的条件、性能测试依据、可复查案例、失效边界”。

第一批需要比较的实现类别可以包括 TI 批处理写入、Rule 按需计算、预计算中间结果、共享参数化框架和专用流程。
产品不会宣称某一类别普遍最好；框架化可能减少重复代码，也可能增加参数耦合和排障成本。

分摊方案的最低验证用例：

- 在定义的舍入与尾差政策下，总量守恒；每个目标份额符合约定公式。
- 零驱动、缺失值、负驱动和负来源按明确政策处理。
- 不同版本、期间与业务切片不相互污染。
- 重跑、累计写入、清空再写和中断重试的语义明确。
- 多级分摊的顺序、循环与共享中间结果有显式约束。
- 在记录的环境与规模上验证耗时、内存和资源冲突。

这些条件需要实际公式、数据与执行证据；静态扫描能够发现部分风险，不能替代运行结果验证。

## 大模型迁移到 Java 的产品边界

先识别业务能力边界和共享依赖，再选择迁移批次。Cube 数量不应直接决定类或微服务数量。
强连通分量、共享写入目标和调度关系用于识别难以拆开的单元；业务边界仍需人确认。

语言无关中间表达需要携带：输入输出契约、粒度、表达式、条件、循环、阶段、参数、外部资源与副作用。
保留未解析动态对象及其影响范围。按功能模块导出上下文，避免一次导出整个服务器。

迁移必须单独处理的语义：

- TI 的 Prolog / Metadata / Data / Epilog 生命周期与外部数据源记录处理。
- Rule 的 N/C 范围、优先级、STET/CONTINUE、聚合与按需计算。
- Feeder 与稀疏计算的适用性，不能把 Feeder 直接当作业务公式。
- 单元格数值/字符串、缺失与零、层级权重、属性和顺序。
- CellPut 与 CellIncrement 的覆盖/累加行为、并发、隔离及失败恢复。
- View、Subset、MDX、框架调用和外部 SQL/文件的运行语义。

迁移准备报告必须同时列出已解释语义、待人工决策语义、测试缺口和阻塞项。
Java 端最终通过功能契约和结果对照验收，不能凭生成代码成功编译认定等价。

## 交互与信息架构

固定显示当前项目、模型、快照时间与更新状态。Demo 是明确的数据源，不冒充客户模型。
多个本地模型存在时让用户选择；只有一个有效候选时可以一键连接。

核心工作区：模型浏览、关系与影响、知识提炼、经验库、迁移准备、任务与设置。
当前版本仅开放已实现入口，未来能力不使用空按钮或虚假数据占位。

统一的对象详情包含：事实摘要、代码/参数、上下游、写入切片、证据与未解析项。
图用于探索局部关系，表格用于精确检索；大图默认分层展开，不把所有节点一次塞进浏览器。
分析结果使用摘要、分页列表和详情，避免把整个 JSON 当成产品界面。

统一状态：未开始、准备、执行、完成、失败、取消、数据源已变化。任务可离开页面继续运行。
能数对象时显示真实 current/total；阶段工作量不同，不将阶段序号伪装为准确百分比。
执行时立即反馈，结束后不额外等待动画或人为延时。

风格以可读性、密度一致、清晰层级和可访问性为准：本地字体与资源、浅/深色主题、可见焦点、键盘操作、文本状态、减少动效、窄窗口可用。
参考 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)；符合若干规则不等于已经完成可访问性合规认证。

## 性能契约

“立即反馈”和“完成分析”分别验收。所有硬件上绝对零延迟无法成立；产品必须通过实测限制可感知等待。
按下菜单先绘制状态，再处理数据。交互基于浏览器下一次绘制测量，参考 [INP](https://web.dev/articles/inp)。

目标（验收环境必须记录硬件、系统、浏览器、模型规模和冷/热状态）：

| 操作 | 目标 | 度量边界 |
| --- | --- | --- |
| 点击到可见反馈 | p95 ≤ 50ms，p99 ≤ 100ms | 下一次绘制；不是服务器完成时间 |
| 热状态菜单/列表首屏 | p95 ≤ 200ms | 本地请求及可用内容绘制 |
| 常见对象详情/检索 | p95 ≤ 300ms | 分页、有界结果，不输出整模型 |
| 后台分析时导航/任务状态 | p95 ≤ 200ms | 分析进行中也必须可用 |
| 长任务 | 及时开始反馈，阶段可观察，可取消 | 不承诺固定分析时长 |
| 连续切换 100 次 | 无无界 DOM/页面缓存增长 | 对比前后内存与在途任务 |

以上是发布门槛目标，不是未经测量的已达成声明。p95 指 95% 的测量不超过此值。
真实数据仅在本机验证；公开压测使用虚构的大模型、汇合图、循环与深链。

架构原则：磁盘保存可重建分析结果；内存只保留有限热点；按内容指纹增量失效；重计算移到后台；列表分页；源码分批读取；图遍历每个节点只展开一次。
晨间更新构建新快照，通过校验后原子切换，期间保留上一份可用快照。该完整更新流程仍需后续实现。

## 迭代与发布门槛

| 阶段 | 核心成果 | 通过条件 |
| --- | --- | --- |
| A 可靠性基础 | 性能根因修复、真实进度、私有导入、隔离缓存、证据边界 | 回归测试、浏览器验证、真实数据只读基准、发布检查 |
| B 语义引擎 | 结构化语法、参数与变量传播、Rule/Feeder 语义、覆盖率报告 | 匿名黄金用例、无法解析项可见、历史结果可重建 |
| C 经验库 | 有版本经验包、评审、适用条件、分摊比较目录 | 至少一种分摊实现可验证识别并能展示反例与取舍 |
| D 迁移准备 | 功能边界、语言无关表达、语义缺口、验证包 | 选定功能完成 TM1 与独立实现结果对照 |
| E 产品发行 | 安装/升级/备份恢复、文档、资源限制与支持边界 | 干净电脑安装、升级不丢私有数据、发布包不含客户内容 |

不以功能数量、漂亮图表、通过一次 Demo 演示或测试总数代替这些门槛。
