# DESIGN MODE — 设计模式（Visual Development 2.0）

> 与探索模式共用同一画布、同一工作区、同一对象身份体系。
> 设计对象**永远**是本地草稿：不部署、不修改模型、不参与服务端血缘计算。

## 1. 模式切换

入口：`/architecture?view=workbench` 顶部「探索模式 / 设计模式」。

| 模式 | 可见内容 | 写入位置 |
|---|---|---|
| Explore | 快照对象、静态关系、Rule/Feeder、人工模块 | 用户工作区 |
| Design | 上述内容 + Cube 草稿 / 维度草稿 / CSV Schema / 设计关系 / Blueprint | 用户工作区（同一文件） |

切换不丢上下文：画布、选中、备注、MDX、人工模块、视口都保留，`design.mode` 随工作区保存。

## 2. 设计对象

| 对象 | ID 前缀 | 关键字段 | 来源标记 |
|---|---|---|---|
| 维度草稿 | `dimdraft-` | 名称、元素、元素类型（S/N） | `DESIGN_DRAFT` |
| Cube 草稿 | `draft-` | 名称、**有序**维度列表、说明 | `DESIGN_DRAFT` |
| CSV Schema | `csv-` | 名称、字段（名称/类型/必填）、来源 | `DESIGN_DRAFT` |
| 设计关系 | `rel-` | 来源、目标、映射、写入策略、模板 | `DESIGN_RELATION` |
| Blueprint | `bp-` | 关联对象 id、生成物摘要、版本、时间 | `DESIGN_DRAFT` |

### 2.1 维度位（DimensionRef）

```json
{"kind": "existing", "name": "Scenario"}
{"kind": "draft", "name": "Product", "draft_id": "dimdraft-xxxxxxxx"}
```

- `kind=existing`：引用当前快照中真实存在的维度，**不留存**成员清单，使用时按快照身份解析。
- `kind=draft`：引用维度草稿，必须给出存在的 `draft_id`；含义是「尚未部署」。
- 顺序即 TM1 维度顺序，保存与生成都按此顺序，绝不使用无序集合。

### 2.2 唯一性与顺序校验

- Cube 草稿维度不得重名（大小写不敏感）。
- 维度草稿元素不得重复、不得为空。
- CSV Schema 字段不得重名。
- 同一目标维度只能有一条映射。

以上在模型层直接拒绝（`422`），不进入保存或生成。

## 3. 创建流程（UI）

1. **维度草稿**：填名称与元素（一行一个）→「创建维度草稿」→ 出现在「设计对象清单」，显示 `dimdraft-…` 并可「引用到 Cube 维度框」。
2. **Cube 草稿**：填名称、维度（一行一个）、说明 →「创建 Cube 草稿」。引用已有维度直接写名称；引用草稿写 `名称@dimdraft-id`。创建后立即出现在画布（虚线节点，标注「Cube 草稿 · 未部署」）。
3. **CSV Schema**：粘贴一行表头 →「解析表头」→ 逐字段确认类型 →「保存 Schema 草稿」。
4. **设计关系**：选择来源（CSV / Cube 草稿）与目标（Cube 草稿）→「建立设计关系」→ 画布出现虚线设计关系边。
5. **映射与生成**：见 `MAPPING_CONTRACT.md` 与 `CODEGEN_BRIDGE.md`。
6. **Blueprint**：见 `BLUEPRINT_SCHEMA.md`。

## 4. 画布语义

| 视觉 | 含义 |
|---|---|
| 实线蓝框节点 | 快照真实对象（Cube / TI / Chore / Dimension） |
| 灰色实线边 | 索引观察（TI 读写、调用、调度） |
| 实线「规则引用」 | Rule 声明式依赖（`SOURCE_CONFIRMED`） |
| 虚线「Feeder 支持」 | 稀疏性支持，不是值流 |
| 黄色虚线节点 | Cube 草稿（未部署） |
| 紫色虚线节点 | CSV Schema 草稿 |
| 虚线「设计关系 · 未部署」 | 用户规划的加工关系 |

设计关系永远不会被当成静态血缘；`provenance = DESIGN_RELATION` 在数据结构与 UI 中同时存在。

## 5. 草稿详情

点击 Cube 草稿：

- 逐条列出维度顺序及每个位是「快照已有维度」还是「维度草稿 + draft_id」；
- 列出以它为目标的映射入口；
- 「查看 Cube 创建说明」→ 规格与步骤（不声称已部署）；
- 「删除此草稿」——只删本地草稿，真实模型不受影响，相关设计关系一并移除。

点击 CSV Schema：字段清单、类型、来源，明确「仅表头，未读取数据行」。

## 6. 保存与恢复

- 与探索状态同一份工作区文件（`architecture-workspace-2`）。
- 保存前校验引用完整性：Cube 草稿引用的维度草稿必须存在；关系引用的 Schema / Cube 草稿必须存在；Blueprint 引用的对象必须存在。
- 恢复后设计对象、顺序、映射、Blueprint 全部回到原状态；画布重新渲染草稿节点。
- 恢复失败（引用失效）时不覆盖原文件，提示保留设计草稿。

## 7. 边界

- 不做完整 Hierarchy 编辑器：维度草稿只有元素列表与类型。
- 不做自由拖拽建边：关系通过「来源 / 目标」下拉建立（选择式优先，保证准确性）。
- 不自动把同名维度当成同一语义：映射必须逐项确认。
- 草稿不会被写入 TM1，也不会进入血缘计算。
- 本轮不支持草稿 → 真实 Cube 的部署脚本执行。
